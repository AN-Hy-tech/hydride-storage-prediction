## Why each one is believed the way it is

1. **`ensemble-headline`** -- The committed files contradict each other, which is itself the evidence that the published pipeline is not the committed one. Even the agreeing file is scored on the validation set that chose the ensemble's members (leak L2).
2. **`ensemble-ci`** -- It is an interval around the headline above, and inherits that row's contradiction.
3. **`best-vs-ensemble`** -- It names a different best model, so the report's test is not the one on disk. Neither carries weight today: both compare test-set errors of models selected on the same data.
4. **`cleanlab-rows`** -- The report's own §6.4 table uses the same 247-row counts. CleanLab removed nothing from the scored test split; the ~239 was never realised.
5. **`overfitting-footnote`** -- The published column is Train − Val in weight percent, which is what `benchmark_model_selection.py:1120` computes. The footnote describes a difference between a log-space CV score and a weight-percent one, which is not a quantity (`hydms/data/target.py`).
6. **`lowest-overfitting`** -- The report's own table shows the lower values; the sentence contradicts it.
7. **`pairwise-randomforest`** -- The conclusion (not significant) survives; the number does not.
8. **`pairwise-others`** -- A model the report calls significantly worse is not, at its own threshold.
9. **`subgroup-robustness`** -- The report's §6.4 table, which is this CSV, shows ExtraTrees ahead in every subgroup. §4.3 rests the ensemble's recommendation on this robustness.
10. **`element-count`** -- Counted from every parsed composition, and asserted in `tests/data/test_load.py`. Probably inherited rather than introduced: the HyStor paper reports 54 for its own 1,282-row release, a different file. It cannot be settled from this repository. If these 1,279 rows are a subset of that release, the release has at least 55 elements too and the paper's own count is wrong; if they are not, nothing here can say what that file contains.
11. **`unique-compositions`** -- 1,149 is right for strings. As *materials* it overcounts: `La1Ni5` and `LaNi5` are one alloy. Anything grouped -- splits, folds, resamples -- uses the canonical key (`hydms.data.canonical.group_keys`), or rows of one material straddle a split.
12. **`europium-row`** -- Europium is absent from CBFV's JARVIS table, and CBFV featurised row 516 anyway with an all-zero property vector (zero mass, zero polarizability). Its `avg_polzbl_divi_atom_mass` of 0.096547 is (5/6) × Ni's value exactly (#16). `extract_features_cbfv.py` never read CBFV's `skipped` list, so 1,279 featurised rows includes one that was not.
